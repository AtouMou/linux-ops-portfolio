# SSH 配置与网络基础 知识总结

## 一、SSH 部分

### 1. SSH 密钥原理

┌─────────────────────────────────────────────┐

│  你（持私钥）  ──签名认证──>  服务器（持公钥）│

└─────────────────────────────────────────────┘

| 文件             | 作用 | 谁能看到     |
| :--------------- | :--- | :----------- |
| `id_ed25519`     | 私钥 | 只有自己     |
| `id_ed25519.pub` | 公钥 | 可以给任何人 |

### 2. 核心命令

*# 生成密钥*

ssh-keygen -t ed25519 -C "email"

*# 复制公钥到服务器（免密登录）*

ssh-copy-id -i ~/.ssh/id_ed25519.pub user@server

*# 手动添加公钥（如果 ssh-copy-id 不工作）*

mkdir -p ~/.ssh

chmod 700 ~/.ssh

cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys

chmod 600 ~/.ssh/authorized_keys

*# 连接*

ssh user@server

ssh -p 2222 user@server

*# 执行远程命令*

ssh user@server "ls -la"

*# 传输文件*

scp file.txt user@server:/path/

scp user@server:/path/file.txt ./

### 3. SSH Config 配置

*# ~/.ssh/config*

Host alias

​    HostName 123.45.67.89

​    User root

​    Port 22

​    IdentityFile ~/.ssh/id_ed25519

### 4. 安全加固项

| 配置                        | 作用           |
| :-------------------------- | :------------- |
| `PermitRootLogin no`        | 禁用 root 登录 |
| `PasswordAuthentication no` | 禁用密码登录   |
| `PubkeyAuthentication yes`  | 启用密钥登录   |
| `Port 2222`                 | 改非默认端口   |

## 二、网络基础部分

### 1. 常用网络命令

*# 连通性测试*

ping -c 4 8.8.8.8

*# 查 DNS 记录*

dig google.com

dig google.com +noall +answer

*# HTTP 测试*

curl -I https://example.com

curl https://example.com

*# 路由追踪*

traceroute 67.112.43.67

*# 查端口占用*

ss -tlnp | grep :80

*# IP 配置*

ip addr

### 2. DNS 记录类型

| 类型  | 作用              | 举例                       |
| :---- | :---------------- | :------------------------- |
| A     | 域名 → IPv4       | `google.com → 142.250.x.x` |
| AAAA  | 域名 → IPv6       | `google.com → 2607:...`    |
| CNAME | 域名 → 域名       | `www → github.io`          |
| MX    | 域名 → 邮件服务器 | `@gmail.com`               |
| TXT   | 域名 → 文本       | SPF 验证                   |

### 3. traceroute 解读

1  172.28.224.1        # 本地网关

2  192.168.43.1        # 家庭路由器

3-5  运营商网络

6   * * *              # 路由器不响应（被防火墙屏蔽 ICMP）

...

16  203.131.243.53     # 最后响应的一跳

17-30  * * *            # 后面的都被屏蔽了

- `* * *` = 那个节点不回答 traceroute（不代表没到）
- 有延迟（ms）= 那一跳响应了

### 4. dig 输出解读

;; SERVER: 172.28.224.1#53    # 你的 DNS 服务器

;; ANSWER SECTION:             # 答案部分

google.com.  0 IN A  108.177.125.102   # TTL=0, A记录

## 三、常见坑点

| 坑                    | 说明                                                 |
| :-------------------- | :--------------------------------------------------- |
| `ssh-copy-id` 失败    | 检查密码认证是否被禁用，尝试手动添加公钥             |
| 覆盖密钥对            | 本地私钥变了，但 GitHub/服务器上的公钥没变，认证失败 |
| `2>&1` 顺序           | 必须是 `>file 2>&1`，不是反过来                      |
| `traceroute` 全是 `*` | 可能被防火墙屏蔽，或目标不存在                       |
