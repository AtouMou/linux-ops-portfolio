# Linux 命令实战 20 场景

> 用真实的场景驱动学习，每个场景直接跑，跑完就懂了。
> 2026-07-24

---

## 场景 1：实时盯着日志，只看 error 和 warn

**什么时候用**：服务器出问题了，你需要盯着日志实时看，但系统日志太杂，99% 都是噪音。

```bash
tail -f /var/log/syslog | grep -i "error\|warn"
```

**输出解读**：只有包含 error 或 warn 的行才会出现，按 Ctrl+C 退出。

---

## 场景 2：统计 syslog 里 error 出现了多少次

**什么时候用**：故障复盘时，需要知道某段时间内出了多少个错误。

```bash
grep -ci "error" /var/log/syslog
```

**输出解读**：输出一个数字，就是包含 error 的行数（-i 表示忽略大小写）。

---

## 场景 3：查 auth.log 登录失败最多的 IP

**什么时候用**：服务器被暴力破解，怀疑有人在外网扫密码。

```bash
grep "Failed password" /var/log/auth.log | awk '{print $11}' | sort | uniq -c | sort -rn | head -10
```

**输出解读**：第一列是失败次数，第二列是来源 IP。次数最高的在最上面。

---

## 场景 4：找所有 7 天内修改过的 .log 文件

**什么时候用**：故障排查时，想快速定位最近被动过的日志文件。

```bash
find /var/log -name "*.log" -mtime -7
```

**输出解读**：列出所有符合条件的文件路径。

---

## 场景 5：预览并清理 30 天前的旧日志

**什么时候用**：磁盘快满了，需要清理旧日志，但不敢直接删，先预览确认。

```bash
# 预览：先看看有哪些文件
find /var/log -name "*.log" -mtime +30

# 确认无误后，再执行删除（去掉注释）
# find /var/log -name "*.log" -mtime +30 -delete
```

**输出解读**：预览模式下只列出文件，不删除。确认无误后取消注释 `-delete` 那行再跑。

---

## 场景 6：内存不够了，查谁是内存杀手

**什么时候用**：机器变卡了，怀疑是某个进程把内存吃光了。

```bash
ps aux --sort=-%mem | head -11
```

**输出解读**：第 1 行是表头，后面 10 行是内存占用最高的进程。`%MEM` 列就是内存占比。

---

## 场景 7：磁盘满了，查哪个目录吃掉了最多空间

**什么时候用**：`df -h` 显示磁盘快满了，但不知道哪个目录在占空间。

```bash
du -sh /* 2>/dev/null | sort -rh | head -10
```

**输出解读**：列出头 10 个最大的顶级目录，从大到小排序。`2>/dev/null` 是屏蔽权限错误噪音。

---

## 场景 8：CPU 飙高，查哪个进程在作妖

**什么时候用**：机器 CPU 100%，需要快速定位是哪个进程。

```bash
ps aux --sort=-%cpu | head -11
```

**输出解读**：和内存那个一样，只是按 `%CPU` 排序。找 `%CPU` 超过 100% 的（多核进程）。

---

## 场景 9：怀疑某进程卡死了，查它的 PID 和状态

**什么时候用**：比如 nginx 响应很慢，想看看它还在不在、状态正不正常。

```bash
ps aux | grep nginx
```

**输出解读**：显示所有包含 nginx 的进程行。每个进程一行，包含 USER、PID、CPU、内存等信息。

---

## 场景 10：查系统负载，评估当前负载是否正常

**什么时候用**：收到告警说负载高，需要判断是真的过载还是正常。

```bash
uptime
```

**输出解读**：

```
14:30:15 up 5 days,  3:22,  2 users,  load average: 0.52, 0.48, 0.41
                                                          ↑1分钟  ↑5分钟  ↑15分钟
```

- 负载数 < CPU 核心数：正常
- 负载数 ≈ CPU 核心数：有点压力
- 负载数 > CPU 核心数：过载

---

## 场景 11：查本机 IP 和网卡状态

**什么时候用**：想知道自己机器的 IP 是多少，或者检查网卡是否 UP。

```bash
ip addr
```

**输出解读**：看到 `inet 192.168.x.x` 就是 IP 地址。`state UP` 表示网卡在线。

---

## 场景 12：测试能不能通百度，超时退出

**什么时候用**：网络连不上了，想快速判断是 DNS 问题、路由问题、还是防火墙问题。

```bash
ping -c 4 baidu.com
```

**输出解读**：
- `4 packets transmitted, 4 received` = 网络通
- `100% packet loss` = 不通，需要继续排查

---

## 场景 13：查哪个进程在占着 80 端口

**什么时候用**：想跑 nginx，但提示 80 端口被占用了，需要查谁在用。

```bash
ss -tlnp | grep :80
```

**输出解读**：显示占用 80 端口的进程，包括进程名和 PID。`-l` 只显示监听中（LISTEN）的。

---

## 场景 14：模拟发一个 GET 请求到百度

**什么时候用**：测试外网是否可达，或者想看某个 HTTP 接口的响应头。

```bash
curl -I https://www.baidu.com
```

**输出解读**：显示 HTTP 响应头。`HTTP/1.1 200 OK` 表示成功返回。

---

## 场景 15：查本机所有监听端口和对应进程

**什么时候用**：做安全审计，想看本机对外暴露了哪些端口和服务。

```bash
ss -tlnp
```

**输出解读**：所有监听中的 TCP 端口。`Local Address:Port` 是本机地址，`Process` 是进程名。

---

## 场景 16：备份 /var/log 目录到 tar.gz

**什么时候用**：系统升级前，需要备份日志目录。

```bash
sudo tar -czvf ~/log-backup-$(date +%Y%m%d).tar.gz /var/log/
```

**输出解读**：
- `$(date +%Y%m%d)` 自动生成日期文件名，如 `log-backup-20260724.tar.gz`
- 备份到 home 目录，不会覆盖原文件

---

## 场景 17：找系统里大于 100MB 的文件

**什么时候用**：磁盘告警，想快速定位哪些大文件占用了空间。

```bash
sudo find / -type f -size +100M 2>/dev/null
```

**输出解读**：列出所有大于 100MB 的文件路径。`sudo` 因为有些目录需要权限才能搜。

## 场景 18：批量重命名一目录下的所有 .txt → .md

**什么时候用**：把所有笔记从 .txt 转成 .md 格式（不改内容，只改扩展名）。

```bash
cd ~/linux-ops-portfolio/notes

# 先预览，确认目标文件正确
ls *.txt

# 确认无误后，执行批量重命名
for f in *.txt; do mv "$f" "${f%.txt}.md"; done

# 验证
ls *.md
```

**输出解读**：用 for 循环逐个重命名。`${f%.txt}` 是 bash 参数替换，去掉 .txt 替换成 .md。

## 场景 19：统计 nginx access.log 里的 UV（独立访客）

**什么时候用**：想知道网站有多少独立 IP 访问过（粗略 UV）。

```bash
# 先确保 nginx 日志存在
sudo tail -1000 /var/log/nginx/access.log | awk '{print $1}' | sort | uniq | wc -l
```

**输出解读**：输出数字 = 独立 IP 数。`awk '{print $1}'` 取第一列（通常是 IP）。

---

## 场景 20：找最大 5 个目录并排序（综合管道）

**什么时候用**：综合练习题，把多个命令串起来，真实场景的终极形态。

```bash
du -sh * 2>/dev/null | sort -rh | head -5
```

**输出解读**：当前目录下最大的 5 个子目录/文件，按大到小排序。`sort -rh` = 人类可读数字逆序排序。

## 场景 21（附加）：快速查进程树，看服务依赖关系

**什么时候用**：想看 nginx 是怎么启动的、父进程是谁。

```bash
ps auxf | grep nginx
```

**输出解读**：带树状结构的进程列表，能看到父子进程关系。

## 场景 22（附加）：杀掉一个卡死的进程

**什么时候用**：某个进程卡死了，温柔地杀不死，需要强制终止。

```bash
# 1. 先查到 PID（假设是 12345）
ps aux | grep 卡死的进程名

# 2. 温柔地让它自己退出（SIGTERM，默认信号）
kill 12345

# 3. 等 5 秒还在就强制杀（SIGKILL，无法捕获）
kill -9 12345
```

**输出解读**：无输出 = 成功。可以再用 `ps aux | grep PID` 确认进程已消失。

---

## 场景 23（附加）：用 wc 统计文件行数、词数、字符数

**什么时候用**：想知道一个文件有多大（不是文件大小，是内容多少行/字）。

```bash
wc -l /var/log/syslog    # 总行数
wc -w /var/log/syslog    # 总词数
wc -c /var/log/syslog    # 总字符数
wc /var/log/syslog       # 三个一起显示
```

**输出解读**：`wc -l` 最常用，比如想知道日志有多少条记录。

---

## 场景 24（附加）：后台运行一个命令，退出终端不中断

**什么时候用**：跑一个很长的脚本，不想开着终端等，但关了终端不能断。

```bash
# 启动时加 nohup
nohup ./long-running-script.sh &

# 或者用 nohup 配合输出重定向
nohup ./script.sh > output.log 2>&1 &

# 查看后台任务
jobs
```

**输出解读**：`nohup` = no hang up，防止终端退出导致进程被杀。`&` = 后台运行。

---

## 场景 25（附加）：快速构建一个命令管道

**什么时候用**：综合题，看你能不能把多个命令串联起来解决实际问题。

```bash
# 场景：找 CPU 占用最高的 3 个进程，提取 PID 和进程名
ps aux --sort=-%cpu | head -4 | tail -3 | awk '{print $2, $11}'
```

**输出解读**：
- `ps aux` 查出所有进程
- `--sort=-%cpu` 按 CPU 逆序
- `head -4` 取前 4 行（含表头）
- `tail -3` 去掉表头，留 3 个进程
- `awk '{print $2, $11}'` 取 PID（第2列）和进程名（第11列）
