## TC-02A Shell 脚本基础：数组

### 基础理解

#### A01 普通变量与数组

普通变量和数组有什么区别？

在什么情况下，你会优先使用数组，而不是分别定义以下变量？

```bash
server1="web-01"
server2="web-02"
server3="db-01"
```

#### A02 数组展开表达式

下面三个表达式分别表示什么？

```bash
"${servers[@]}"
"${#servers[@]}"
"${!servers[@]}"
```

请分别说明它们适合用在什么场景。

#### A03 `@` 与 `*` 的区别

请解释以下两个表达式在双引号中的区别：

```bash
"${servers[@]}"
"${servers[*]}"
```

哪一个更适合遍历数组或向命令传递参数？为什么？

#### A04 删除元素后的索引

执行下面代码后：

```bash
colors=("red" "green" "blue")
unset 'colors[1]'
```

请回答：

1. 数组长度是多少？
2. 剩余的索引是什么？
3. `blue` 的索引是否会自动从 `2` 变成 `1`？
4. 如何同时遍历剩余元素的索引和值？

### 代码分析

#### A05 数组展开与引号

下面代码有什么问题？

```bash
files=("access.log" "old access.log" "*.log")

for file in ${files[@]}; do
    echo $file
done
```

请指出可能发生的错误，并写出更安全的版本。你的回答需要解释：

1. `old access.log` 可能发生什么？
2. `*.log` 可能发生什么？
3. 为什么输出变量时通常也应该写成 `"$file"`？

#### A06 使用数组保存命令参数

为什么下面这种保存 `curl` 参数的方式不够可靠？

```bash
curl_options="--silent --connect-timeout 3 -H Authorization:\ Bearer\ abc123"
curl $curl_options https://example.com
```

为什么数组更合适？请使用数组重写，并说明数组如何保留每个命令参数的边界。

### 实战设计

#### A07 批量检查服务状态

现有以下服务：

```bash
services=("nginx" "ssh" "docker")
```

请写一段 Bash 代码完成以下要求：

1. 遍历所有服务。
2. 使用 `systemctl is-active --quiet` 检查状态。
3. 把异常服务保存到 `failed_services` 数组。
4. 最后输出检查总数、异常数量和异常服务名称。
5. 如果存在异常服务，脚本返回非零退出状态。

#### A08 关联数组的使用场景

什么时候应该使用关联数组，而不是普通索引数组？

请至少说出两个适合使用关联数组的运维场景，并分别说明其中的“键”和“值”是什么。可以从以下方向思考：

- 服务与端口
- 主机名与 IP 地址
- 检查项目与检查结果
- HTTP 状态码与出现次数

#### A09 Bash 数组的局限

Bash 数组有哪些局限？

什么时候你会放弃 Bash 数组，改用文本文件、CSV、JSON、`jq`、Python 或数据库？请至少从以下方面回答：

1. 数据是否需要持久化。
2. 数据结构是否复杂或嵌套。
3. 数据量是否较大。
4. 是否需要并发读写或多人共享。
5. 脚本是否必须兼容 POSIX `sh`。

## TC-03 权限与用户管理

### 基础理解

#### P01 权限匹配规则

Linux 判断文件权限时，如何在属主、属组和其他人三组权限之间进行匹配？

假设文件信息如下：

```text
-rwx------ 1 alice devops 1234 Jul 25 10:00 file.txt
```

`bob` 属于 `devops` 组，他能执行这个文件吗？为什么？

#### P02 文件权限与目录权限

文件上的 `r`、`w`、`x` 和目录上的 `r`、`w`、`x` 分别表示什么？

为什么“能否删除一个文件”主要取决于其父目录的权限，而不是文件自身的写权限？

请进一步分析以下情况可能出现什么结果：

1. 对目录只有 `r`，没有 `x`。
2. 对目录只有 `x`，没有 `r`。
3. 对目录有 `w` 和 `x`。

#### P03 从 `/etc/passwd` 查找用户

下面命令的作用是什么？

```bash
grep "bin/bash" /etc/passwd
```

请回答：

1. 为什么它通常比 `cat /etc/passwd | grep "bin/bash"` 更直接？
2. 它查到的是“系统中的所有用户”吗？
3. 它能否严格保证匹配的是登录 Shell 字段？
4. 如果要精确筛选第七个字段等于 `/bin/bash` 的账号，你会怎么写？
5. `/bin/bash`、`/usr/sbin/nologin` 和 `/bin/false` 作为登录 Shell 时通常分别表示什么？

### 实战判断

#### P04 脚本没有执行权限

执行以下命令时报错 `Permission denied`：

```bash
./deploy.sh
```

但下面的命令可以正常运行：

```bash
bash deploy.sh
```

请说明原因，给出解决命令，并解释这两种执行方式对脚本文件权限的要求为什么不同。

#### P05 `usermod -G` 的风险

下面命令有什么风险？

```bash
sudo usermod -G devops alice
```

应该如何修改？为什么 `-a` 与 `-G` 经常需要一起使用？执行后为什么有时需要重新登录才能看到新的组身份？

#### P06 Nginx 正常运行但网站返回 502

一台 Linux 服务器上的 Nginx 状态为 `active (running)`，但访问网站返回 `502 Bad Gateway`。

请按合理顺序给出排查过程，并说明每一步准备验证什么。至少考虑：

1. Nginx 错误日志。
2. 上游应用或后端服务状态。
3. 监听地址和端口。
4. Nginx 上游配置。
5. Unix Socket 或目录权限。
6. SELinux 或 AppArmor。
7. 防火墙与网络连通性。

#### P07 脚本在 Crontab 中失败

为什么在交互式终端中能运行的脚本，放入 Crontab 后可能失败？

请至少说出三个常见原因，并说明如何排查。回答时可以考虑：

- `PATH` 等环境变量
- 当前工作目录
- 相对路径
- 执行权限和解释器
- 文件读写权限
- 标准输出与标准错误
- 用户身份

### 综合题

#### P08 `root`、`sudo` 与账号文件

请解释以下概念之间的关系：

- `root` 用户
- `sudo` 提权机制
- `/etc/passwd`
- `/etc/shadow`

为什么 `/etc/passwd` 通常允许普通用户读取，而 `/etc/shadow` 只有特权用户可以读取？

`root` 和 `sudo` 的本质区别是什么？请从身份、授权范围、操作审计和风险控制几个角度回答。

#### P09 创建新同事账号

需要为新同事 `alice` 创建账号，要求：

2. 家目录为 `/home/alice`。
3. 可以使用 `sudo`。
4. 加入 `devops` 附加组。
5. 设置初始密码。

请写出完整命令，并说明如何验证：

- 用户的 UID、主组和附加组
- 家目录与登录 Shell
- `sudo` 权限
- 账号是否可正常登录

如果系统是 Ubuntu/Debian 与 Rocky/RHEL，授予管理员权限时使用的组名可能有什么差异？

#### P10 权限位正确但操作仍然失败

`ls -l` 显示的属主、属组和 `rwx` 权限看起来都正确，但操作仍然失败。

请至少说出三种“传统权限位之外”的可能原因，并分别说明排查方法。可以从以下方向思考：

- 父目录权限
- ACL
- SELinux

## 综合模拟题

#### C01 最小权限原则

什么是最小权限原则？

假设部署脚本只需要重启 Nginx，你会选择让部署用户拥有完整 `sudo` 权限，还是只允许执行指定命令？请说明理由以及大致配置思路。

#### C02 批量用户检查

请设计一个 Bash 脚本，实现以下需求：

1. 从数组中读取一组用户名。
2. 检查用户是否存在。
3. 检查其登录 Shell 是否为 `/bin/bash`。
4. 把不存在的用户、不可交互登录的用户分别保存到不同数组。
5. 最后输出分类汇总，并根据检查结果设置退出状态。

请重点说明数组在这个任务中承担什么作用，以及你会如何避免直接用模糊的文本匹配判断用户属性。

#### C03 权限故障排查方法

普通用户执行 `/opt/app/deploy.sh` 时收到 `Permission denied`。文件本身是 `755`，属主和属组看起来也正常。

请给出一套由外到内的排查顺序。至少覆盖：

1. 当前用户身份和组。
2. 路径中每一级目录的权限。
3. 文件系统挂载选项（例如 `noexec`）。
4. 脚本解释器与 Shebang。
5. ACL。
6. SELinux 或 AppArmor。
